# 多agent研究与产品迭代协议 0.1

目的：将问题研究、方案设计、独立反驳、实施整合、验证与版本决策变成可复用工件。协议和工具尚未被多轮对照证明提升效率；本次完成一次设计协作试运行。

## 一轮怎样工作

1. 主代理冻结目标、输入版本、允许变化项、反证条件、输出位置与验收；登记任务及依赖。
2. owner研究或设计，以证据包交接；独立reviewer检查，不由owner自我通过。
3. reviewer给accept/revise/reject/inconclusive及证据。返工发给owner，保留上一稿和裁决理由。
4. 主代理整合已审阅建议；业务实施先过模块回归，再过共同案例及配对实验。
5. QA核对声明与证据；形成继续、回退或暂停结论，提交版本记录。结果为零或负也可通过科学性验收。

研究方案可以先并行；输入接口未变时下游基于版本化fixture推进。真正的集成必须换成真实模块再验收，不能拿mock通过代替模块完成。

## 模型和职责

本轮使用：gpt-6-astra负责算法/状态/契约推理，gpt-5.6-sol负责产品入口与角色设计，gpt-5.6-terra负责协作协议与可检验性，主代理整合与交叉审查。模型不是永久绑定职位，按任务表现替换，保留模型/任务/评审记录。同一任务owner和reviewer必须是不同执行者；角色名称不同但背后同一执行者不算独立审查。

当前Sites环境只允许主代理编辑项目、提交与发布。subagent提交研究、规格、补丁文本或独立资产；主代理串行应用。其他允许独立分支的环境，可各模块分支实施再由集成负责人合并，但不绕过当前限制。

## 任务包必填

`id, kind, owner, reviewer, status, dependsOn, inputRefs, contractVersion, outputs, acceptance, falsifier, maxRevisions, evidenceRefs, reviewEvidenceRefs, reviewDecision, limits`。

状态：queued → active → review → accepted；也可blocked/rejected/inconclusive。accepted必须有独立审阅JSON（taskId、reviewer、decision、reviewedAt、inputHashes）、产物及证据引用；结构工具只能检查这些记录存在，不验证证据真伪或研究质量。设计被接受只解锁按契约研究，不代表业务模块已实现。

交接包须写：主张、输入版本/配置/种子、输出、支撑证据、假设、限制、复现方法、下一动作。涉及算法或实验必须给最小反例/运行数据，不接受只有漂亮结论的交接。

## 首轮异步任务队列

`workflow/v2.json`是唯一任务状态清单。先接受契约设计，再并行研究城市、算法、账务、服务、治理、角色界面和实验预注册E1a。E1b是真实实验运行，必须等待I1集成实施，并提交run_artifact/common_seeds/config_diff三类证据；P1依赖E1b，mock不能解锁效果主张。集成必须等待真实模块验证；项目页的架构文案可早做，效果主张须等证据，不提前宣布。

研究者/产品agent不能决定已签承诺，指标agent不能修改规则，设计agent不能编造账目。模块建议产生冲突时由主代理形成决策记录，不用多数投票替代领域证据。

## 反馈与停止

- 匹配反例→算法owner，先登记回归规格；账不平→账务owner并阻断经营结论。
- 比较条件污染→实验owner重新锁定配置；行为证据缺失→保留假设和阈值，不用模拟冒充访谈。
- 角色决策不清→产品owner；接口破坏→契约owner通知所有下游并迁移fixture。
- 每项默认最多两轮修订；超限则标blocked/inconclusive并拆解更小问题。预算限制不能被解释成“到轮次就算完成”，也不允许无限调参直到出现正效应。
- 发布须满足明确的实施与验证任务，而不是所有文档都存在。本轮保持v1发布状态。

## 可复用工具和边界

`node scripts/check-v2-workflow.mjs`验证清单；加`--ready`输出依赖已满足的queued任务。检查：重复ID、依赖缺失/环、owner/reviewer相同、accepted缺证据或依赖未完成、引用路径越界、模块声明中的非法读写边、fixture未来信息字段/时间及单位。

它不调度agent，不调用模型，不提交代码、不运行产品，不证明运行时授权/隔离/幂等。真实执行仍由主代理发起工具和收集结果。

## 如何衡量这套工作流是否有效

每轮记录：任务数、退回原因、修订轮次、整合前/后发现的缺陷、独立复现比例、发布主张证据覆盖、实际用时及可得的模型成本。不可见成本写unknown，不估造token账。

积累多轮后用相近规模任务比较有/无独立审查的返工与漏错，控制任务复杂度；不能因为用了三个agent就宣称提高效率。本轮证据仅是发现并修正了设计边界问题，见run-001.md。
