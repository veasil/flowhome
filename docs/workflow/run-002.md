## 本轮目标

把运行 001 的架构草案变成一个可操作的研究型 MVP：同一净水设备案例贯穿居民、运营者、外部服务商与下一位接手者；研究台运行持续城市、四组配对实验和财务桥；项目页说明价值主张、证据与边界；v1 保留在 `/v1`。

本轮不把原型界面写成真实交易系统，不声称治理、身份授权、支付、服务商排班或 AI 训练已上线。

## 实施链路

1. **冻结契约**：沿用 C0 的钱、时间、角色、观察/真值隔离和模块写权约定。
2. **并行实现**：城市/算法/实验与承诺/账务/履约分开工作，界面由集成负责人依赖稳定导出接口组装。
3. **主代理采用**：检查子 agent 产物，不直接把交接结论当成已通过；接入后以仓库最终文件为审阅对象。
4. **模块回归**：领域状态机覆盖幂等、陈旧版本、失败原子性、拒单重排、合同政策冻结、申诉回避与现金桥；城市引擎覆盖 F01/F02/F06/F07/F08、可复现、持续流入与容量冲击。
5. **共同案例**：`/live → /ops → /live → /partners → /live → /partners → /live` 操作同一浏览器本地案例，所有命令经过 `dispatch`，各入口通过 `project` 查看角色投影。
6. **配对实验**：10 个共同种子 × 3 个持续流入情景 × 4 个策略组，共 120 次真实引擎运行；A/B 和 C/D 各自只改变预测排序。
7. **独立 QA**：审阅最终源文件、运行输出、可视界面与范围声明。QA 发现的问题回到相应 owner，主代理修正后重新送审。
8. **版本化发布**：只有审阅通过的任务才改为 accepted；提交后记录完整 commit SHA、工件 hash、Site version 与部署状态。

## 关键修订与缺陷拦截

- 领域幂等最初的风险是重放旧命令时返回旧状态，可能把已发生的退出“回滚”。实现约束改为：返回当前传入 state，只复用原 result；回归测试覆盖选择后签约、退出再重放选择。
- 匹配逻辑先枚举全部可行物件、服务商和窗口，再排序。避免“最便宜候选来不及 → 直接买新品”的短路。
- 城市正常实验持续到第 103 周仍有新需求；停止新增只属于显式 `exit` 情景，不能混入配对实验。
- 预测只读取公开快照，规则点估计明确标注为基线；实验结果允许为零或负，不以调参得到正结果作为通过条件。
- 居民的成功自售事后净支出和事前概率期望分开显示；概率由用户调整，不能冒充市场预测。

## 范围缺口（必须随版本公开）

1. 单案例的服务商任务是状态演示，**没有**服务商容量日历、窗口预留与并发排班；S1 只能按“拒单/重排/任务与报酬可追溯”的原型范围验收，不能按完整运力系统验收。
2. 治理是版本化政策、申诉与利益冲突回避的模拟，**没有**成员身份、投票法定人数、授权链或真实社会企业章程。
3. 研究台预测是基于过去 8 周公开需求的加权规则点估计，**不是**训练、校准或部署的 AI 模型；只能作为可替换算法内核的基线。
4. 界面使用浏览器本地状态模拟角色切换，**不是**生产级服务端认证、权限隔离、支付或隐私控制。
5. 单案例与城市模型的费用/品类假设不同，二者不能拼成同一套经营账；项目页只能说“展示从服务原型到城市实验的连接”。

## 发布判定

发布研究型 MVP 的门槛是：构建与浏览器主路径通过；领域与引擎回归通过；120 次工件可重现；独立 QA 已检查最终文件；项目页和下载文档公开上述缺口；v1 可恢复。发布不等于 S1/G1 的生产能力完成。若工作流 DAG 要求所有模块 accepted 才允许 P1，可把本次发布定义成“研究原型候选”，或者显式新增 `P0 research_mvp_release`；不要伪造 S1/G1 的完成度。

## 本轮工作流自身能声称什么

可以声称：任务契约、owner/reviewer 分离、外部交接区、集成门、回归门、真实配对实验门、范围声明门和部署门已经形成一条可复用流程；本轮发现并预防了幂等回滚、候选短路、实验窗口混淆与范围膨胀。

仍不能声称：多 agent 一定比单 agent 更快、更便宜或质量更高。时间与模型成本不可得，记为 `unknown`；协作收益需要后续相近规模任务做对照。
