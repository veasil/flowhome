## 已采纳的交叉评审修订

1. 产品初稿从退出起步，改为购买前需求与退出方案比较；这才对应购买顾虑。
2. 治理UI可在运营台，但不能把治理权都交运营者；居民/服务商有就地参与和申诉，利益冲突回避。
3. 共享事实不意味着各角色可见全部字段；模拟研究真值与算法观察输入分开。
4. 工作流示例曾把“居民选择”直接产生合同，改成请求，只有执行器校验并留存后确认合同。
5. 服务能力预测不同于已锁定预约；服务商拒单不解除组织对居民的既定责任。
6. 静态校验器只能检查声明，不证明运行时隔离、授权或幂等；相关性质保留为下一阶段验收。

## 审阅结论

产品agent独立交叉评审提出三项必改：购买前流程、治理权限、事实可见性。主代理逐条写入v2-system/v2-contracts。模块agent的接口建议与此兼容；工作流agent复核确认需要区分静态验证与运行时测试，并修正mock因果。C0仅按设计层接受，未授予任何业务实现通过状态。
