# 产品与生活交接

[文档导航](README.md) · [研究台](research-workbench.md)

## 为什么从 home 出发

FlowHome 关心青年与居住：人可以流动，同时拥有平等、温暖、轻负担、有连接的城市生活。家的组成不只有房屋产权，还包括可用的空间、熟悉的物件、附近的人、日常习惯和记忆。

“共享”意味着部分资源和经验能够被他人接续；“分布式”意味着家的支持可以由多个地点、物件和关系共同提供。关系与记忆不能被系统自动转让，用户应决定是否分享以及分享什么。

最初的产品切口是离开与到来之间的生活交接。愿景保留空间与关系维度，首轮模拟聚焦可记录、可履约的物件和服务。

## 谁在参与

| 角色 | 需要什么 | 系统需要明确什么 |
| --- | --- | --- |
| 阶段居住者 | 合适的物件、可理解的总成本、退出路径 | 偏好、期限、预算、可接受的服务条件 |
| 离开的人 | 按时交接、减少处置负担 | 意向与正式承诺、检测和交接窗口 |
| 到来或接手的人 | 可靠物件、可承受价格、及时可用 | 成色、适配性、服务与费用 |
| 本地服务者 | 可执行排程、明确报酬 | 运输、安装、检测、整备能力与责任 |
| 共益运营主体 | 可持续提供协调服务 | 资金、容量、承诺敞口与规则透明度 |
| 研究者与开发者 | 比较机制并改善系统 | 版本化数据、模型假设、实验与事件证据 |

共益运营主体、本地服务网络和成员治理是组织设计，不表示已经成立了具有特定法定资格的组织。

## 首个完整故事：净水设备

1. 小栖登记居住期限、预算和使用需求；预计离开时间是意向。
2. 系统筛除无法按时安装、条件不适合或服务无法覆盖的方案。
3. 比较购买、维护、服务和退出安排，分别列出实际费用、估计残值和有条件的承诺。
4. 小栖自主选择，也可以等待、拒绝推荐或自行购买。
5. 运营方确认可承担的安排；系统占用对应的物件、服务容量与风险额度。
6. 使用期间记录维护和意向变化，变更意向不自动视为违约。
7. 离开时按确认条件检测、回购或交接，再整备给下一位使用者。
8. 如果下一位接手者取消，系统仍按已经确认的回购条件处理，并记录库存、现金与新增服务任务。

办公椅用于展示可流转选择；床垫用于展示卫生、成色、个体偏好等条件不满足时，拒绝不可靠承诺或提供替代方案。

## 个人行动如何形成市场

提前表达需求与释放意向，使城市供需从“现在谁在卖”扩展到“未来某时某地有哪些可用资源”。协调者据此安排检测、运输和资金，并提出附条件的方案。参与者的接受、拒绝和实际履约，再改变未来的供给与需求。

这个过程需要区分四层：

| 层次 | 示例 | 能否直接计作成交 |
| --- | --- | --- |
| 意向 | 预计半年后离城 | 否 |
| 预测 | 某片区下月可能需要若干办公椅 | 否 |
| 确认承诺 | 约定检测条件、窗口和价格的交接 | 否，尚需履约 |
| 已完成事件 | 交付完成且退出款已收到 | 按对应事件口径计入 |

提前协调可能提高匹配率，也可能造成同款过度推荐、集中释放、库存积压和资金紧张。因此“市场形成”是需要观察的过程，不能用一张不断增长的交易额图表证明成功。

## 共益如何进入规则

可负担性、服务可达性、新成员参与、劳动报酬和经营持续性必须一起被观察。每次降低用户价格，都要解释谁承担差额；每项回购承诺，都要说明由谁履行、在什么条件下成立。

信任机制分别记录信息完整度、物件检测、用户履约和服务方履约。拒绝推荐不受惩罚；无历史记录的新成员应有检测、分阶段履约或人工复核的参与路径，不用职业声望或学历生成泛化信用分。

## 首轮边界

首轮交付是模拟研究原型，不涉及真实收付款、信用筛选或真实回购承诺。房屋转租、跨城市网络、复杂资产所有权、真实商家试点属于后续范围。与房屋及服务有关的真实责任，应在进入试点时另行确定，不能从演示自动延伸。
