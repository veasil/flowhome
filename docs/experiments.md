# 计算机模拟实验与指标

[文档导航](README.md) · [原始验收基线](execution-acceptance-v1.md)

> 当前未提交实验输出。以下是实验协议；表格、机制假设和预期现象都不是已测得的效果。

## 研究问题

提前表达计划、协调购买与退出，是否能够在可承担的经营风险内改善用户成本、需求满足和物件流转？收益与负担如何分布在不同预算、居住期限和参与历史的人群之间？

这一问题需要观察数据生成过程、参与者选择、服务约束与失败情景，不能由“交易额增长”单独回答。

## 对照设计

| 策略 | 规则 | 主要比较目的 |
| --- | --- | --- |
| B0 | 自由购买与事后出售 | 无提前协调时的基线 |
| B1 | 提前登记与匹配 | 提前信息与协调的作用 |
| B2 | 预测协调购买建议、报价与资源 | 预测及反馈决策的增量效果与风险 |

三种策略使用相同人口、初始资产、偏好、外部事件、成本结构及外部随机数；策略引起的采纳、库存和后续供给变化属于结果，不强行抹平。共益补贴、外部服务和资源条件如有不同，需要单列，不能归功于算法。

采用按实体和时间固定的外部随机流，并将采纳等策略相关随机过程分开。记录所有随机种子和版本，避免多执行一次随机调用就改变整个外部世界。

## 运行矩阵

- 标准情景，加集中离城、需求下降、服务容量下降三项压力情景。
- 每个情景比较 B0/B1/B2，使用 10 个固定评估种子：核心矩阵共 4 × 3 × 10 = 120 次运行。
- 另做推荐采纳率和预测误差的低/中/高敏感性检查。具体水平和是单因素还是交叉设计，在运行前登记，不计入上述 120 次。
- 调参种子与评估种子分开。看过评估结果后再调参，需要更换独立评估种子并保留前次记录。
- 同种子进行策略配对比较，报告每种策略的均值、范围、配对差值和失败次数。

不设 B2 必须胜出的门槛。无法完成或现金不足的运行也要报告，不能只平均成功样本。

## 指标口径

| 指标 | 定义 | 必须同时展示 |
| --- | --- | --- |
| 用户净使用支出 | 实际已付购入/服务/维护等支出减实际已收退出款 | 纳入费用、观察窗口、未完成退出数量；预计残值另列 |
| 需求满足率 | 时间窗内满足硬条件的需求数 / 到期有效需求数 | 分子分母；未到期需求不计入 |
| 闲置时间 | 可再次使用到下一次使用之间的时间 | 已接续物件分布、期末仍闲置数量及已等待时长 |
| 按时履约率 | 在承诺窗口内完成的到期承诺数 / 到期承诺总数 | 承诺类型、取消/逾期处理口径 |
| 服务利用率 | 已占用容量 / 同期可用容量 | 服务类型及单位，不能混合车次与工时 |
| 单笔贡献 | 对应收入减已定义的直接成本 | 服务劳动报酬、检测/整备/运输等成本范围 |
| 经营持续性 | 最低现金余额、库存估值、未到期承诺敞口 | 三者分列，固定成本假设另列 |
| 群体结果 | 按预算、居住期限、新老成员拆分以上指标 | 各组人数、需求数、分母与未服务者 |

分母为零时显示“不适用”，不要显示 0% 或 100%。取消规则预先定义并保留审计记录，不能通过移除失败需求抬高满足率。跨期成本比较要交代服务时长与期末仍在用资产，避免短期看起来便宜只是尚未结算。

## 一个实验记录应包含什么

实验问题与事先假设、数据版本与校验值、引擎及代码版本、case、完整参数、种子集合、运行起止范围、各次运行状态、原始事件、账目、指标口径和解释。

建议每次实验输出 metadata、config、metrics、events、ledger 及说明报告。导出形式是实现建议，当前仓库没有这些结果文件。

## 如何解释结果

集中离城可能同时增加物件供给和运输需求；提前匹配可能减少等待，也可能因取消而增加库存与资金压力。解释必须引用对应运行、事件与账目，不能只讲合理故事。

模拟结果只能说明在已声明规则和参数下发生什么。真实需求强度、付费意愿、预测有效性、服务成本和长期共益效果，仍需后续试点验证。

## 失败判据

未来信息泄漏、预置胜出结果、只挑成功种子、不同策略使用不一致外部条件、群体指标无分母、账目与事件无法对齐，均使相应实验不通过。修复后重跑并保留修订记录。
