> 这是目标演示脚本，不是已完成的功能验收记录。展示前应核对现场版本能否执行各步骤；尚未实现的环节用设计说明呈现，不伪造运行结果。

| 时间 | 操作与叙事 | 观众应看懂 |
| --- | --- | --- |
| 0:00–0:45 | “小栖在这里住一年。她需要好好生活，也希望离开时不必推倒重来。” | 家的连续性与流动可以并存 |
| 0:45–1:30 | 展示当前数据版本及模拟标签，加载净水设备主 case | 接下来看到的是哪份模拟数据 |
| 1:30–2:30 | 登记居住期限、预算和偏好，比较候选方案 | 购买价格之外的使用成本与退出条件 |
| 2:30–3:30 | 切到城市图，看同品类需求与未来释放 | 一个人的计划怎样进入城市供需 |
| 3:30–4:30 | 选择方案，查看承诺、安装、使用与退出 | 推荐如何变成有责任主体的安排 |
| 4:30–5:30 | 追踪检测、整备和下一位接手，再触发接手者取消分支 | 接续失败时，物件、现金与义务如何变化 |
| 5:30–6:30 | 查看运营账目和服务劳动报酬 | 用户省下的成本由什么支持，风险由谁承担 |
| 6:30–7:30 | 进入研究台，对照 B0/B1/B2；调整容量或切换压力 case | 底层规则可以被检验，不保证某策略胜出 |
| 7:30–8:00 | 回到群体结果及尚未验证的问题 | 共益目标、真实试点与后续协作方向 |

## 三句讲解重点

- “一个人的离开，可以成为另一个人的安顿条件。”
- “当这些计划被表达、协调和履行，个人行动才逐步形成市场。”
- “研究台让我们检查这套市场对谁有效、成本在哪里、哪些承诺承担不起。”

## 展示前检查

明确当前数据计数、case、种子和引擎版本；重置到固定状态；核对地图、账目与结果使用同一运行；确认取消分支能显示风险；核对桌面键盘操作与手机阅读；长任务显示进度。

性能目标沿用原基线：在交付记录列明的桌面设备和浏览器上，10 次标准单情景重算至少 9 次在 3 秒内完成。尚未测量前不得宣称达标。

如果在线演示不可用，可以直接使用 README 和文档讲解产品及机制，并明确无法现场验证计算；不能以静态说明替代算法验收。
