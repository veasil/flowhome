# 数据版本与模拟场景

[文档导航](README.md) · [研究台](research-workbench.md)

> 下述字典、版本协议与 case 标识为本次文档细化的建议规格。仓库尚未包含生成器或完整数据集，也未测得当前演示的实际实体数量。

## 四种版本不能混淆

| 标识 | 变化时机 | 用途 |
| --- | --- | --- |
| schema_version | 字段、类型或语义变化 | 判断数据能否被读取 |
| dataset_id + dataset_version | 同一数据系列的记录、生成规则或来源变化 | 固定实验输入 |
| engine_version | 算法、规则或计算语义变化 | 固定计算方式 |
| run_id | 每次运行或重置后建立新会话 | 关联图表、日志、账目和指标 |

一个网站发布版本可以包含多个数据版本；同一份数据可以由不同引擎运行。数据快照不可原地改写，修订后生成新版本并记录原因。

建议数据清单至少包含：来源类型、生成器版本、随机种子、生成时间、模拟时间范围及单位、各实体实际数量、地理精度、已知限制、内容校验值和数据来源说明。真实数据还需记录授权范围与去标识方式。

以下是**未生成的目标配置示例**，不是已存在的数据清单或运行结果：

```json
{
  "dataset_id": "flowhome-standard-city",
  "dataset_version": "0.1.0",
  "schema_version": "0.1.0",
  "source_type": "synthetic",
  "status": "planned",
  "generator_version": null,
  "seed": 42,
  "time_unit": "week",
  "horizon_weeks": 104,
  "target_counts": {
    "districts": 3,
    "residents": 1000,
    "initial_items": 600,
    "product_models": 30,
    "service_providers": 8
  },
  "actual_counts": null,
  "geography": "schematic",
  "content_hash": null
}
```

生成后须补齐实际数量、版本与校验值。运行过程中新产生的物件或事件数量与初始数量分别显示。

## 建议实体字典

| 实体 | 核心字段 | 语义约束 |
| --- | --- | --- |
| Resident 居民 | id、片区、预算、居住期限、偏好 | 收入预算用于负担判断，不转化为人格信用 |
| Intent 意向 | id、resident_id、需求/释放、时间窗、updated_at | 可变更；不自动形成违约 |
| Demand 需求 | id、resident_id、品类、硬条件、有效时间窗 | 同一需求不得被重复满足 |
| ProductModel 型号 | id、品类、适配条件、维护要求 | 型号与具体物件实例分离 |
| Item 物件 | id、model_id、拥有者、使用者、位置、状态 | 同时段最多一个排他性使用者 |
| Provider 服务商 | id、服务类型、片区、逐期容量、费率 | 服务耗时计入容量 |
| Offer 候选方案 | id、需求、物件、费用分项、预测、到期时间 | 推荐和报价不等于确认承诺 |
| Commitment 承诺 | id、责任主体、条件、窗口、锁定条款、状态 | 模型更新不得静默修改已确认条款 |
| ServiceTask 任务 | id、物件、服务商、起止期、依赖、状态 | 安装必须晚于必要的运输与整备 |
| Event 事件 | id、发生时间、记录时间、实体引用、类型、来源 | 实际事件与预测分别标记 |
| LedgerEntry 账目 | id、event_id、账户、流入/流出、金额 | 转账对账；现金和残值估计分开 |
| Run 运行 | id、版本集合、case、参数、种子、时间范围 | 图表、账目、指标关联同一运行 |

金额实现建议用人民币分的整数保存、界面显示元；时间步用周，服务窗口采用统一半开区间 [start, end)。若实际采用日粒度，需要显式修改协议，不能混用单位。

## 数据状态与信息边界

来源使用 synthetic（模拟）、observed（观察）、mixed（混合）标签；混合数据还需逐记录或逐字段保留来源。事件另带 planned（意向）、predicted（预测）、committed（确认）、completed（完成）等语义，来源与业务状态相互独立。

模拟器可以预生成未来事件，但算法只看到当前及此前的记录和明确披露的意向。预测误差通过预测快照与之后发生的事件比较；不得让引擎读取未来成交者或取消结果。

记录发生时间和系统获知时间，避免回填数据被误当成过去已知的信息。

## “使用模拟数据”场景目录

所有 case 从固定快照启动。下列标识是建议，具体扰动周次和幅度应在实现的配置中记录并随运行导出。

| case | 叙事或扰动 | 重点检查 |
| --- | --- | --- |
| standard-water | 小栖的净水设备完整周期 | 需求、选择、使用、退出、下一位接手与结算 |
| shorter-stay | 居住期限从 12 个月变为 6 个月 | 可用方案与净支出变化，月份到周的换算规则需明确 |
| new-only | 仅接受新品 | 二手方案移除，个人偏好不被网络收益覆盖 |
| office-chair | 办公椅的接手安排 | 成色、可用时间和运输条件 |
| mattress-boundary | 床垫不满足循环条件 | 拒绝保证或替代方案及原因 |
| concentrated-exits | 某段时期集中离城 | 释放供给、库存、运力、风险与新报价 |
| demand-drop | 同品类需求下降 | 未匹配库存与资金压力 |
| capacity-drop | 指定周服务容量下降 | 排程延迟、替代容量或拒绝新承诺 |
| successor-cancels | 后续接手者取消 | 已确认回购保留、库存与现金更新 |
| cash-shortage | 下调周转资金 | 限制新增承诺，不产生隐性透支 |
| newcomer-and-default | 新成员参与、正式承诺未履约 | 新人路径与失约记录分开处理 |

前三项压力情景为 concentrated-exits、demand-drop、capacity-drop，与原验收基线一致；其余为交互和异常分支，不自动增加原基线的必跑压力实验数量。

## 最小质量检查

ID 唯一、引用完整、数量与清单一致；金额和时间单位统一；期初资产与台账可对齐；物件不可重复占用；服务任务依赖有效；未来信息不可进入决策视图。

生成器至少表达五种关联：迁居与需求/释放、价格与接受意愿、维护与状态/残值、集中离城与运力、推荐采纳与未来供给。独立随机生成各表而无这些关联，无法支持市场反馈研究。

固定种子只解决随机输入的一部分问题，还需固定生成器、引擎、参数与确定性排序。对照实验的外部随机数应按实体和时间固定，避免策略分支改变抽样顺序。
