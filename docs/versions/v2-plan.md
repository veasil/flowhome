# Flowhome v2：角色工作流、可兑现匹配与可比实验

状态：下一版已立项，尚未实现。来源：2026-09-18用户查账与“先沉淀这一版”的决定。

## 核心目标

回答两个独立问题：居民愿意为更可预期的退出支付多少；在相同服务责任下，预测能否降低组织履约与周转成本。不得以“必须胜过B0”为验收目标，不为取得正向结论调参。

## 系统界面与结构角色

|角色|界面|需要作的决定|关键账目/信息|
|---|---|---|---|
|居住者|我的居住与退出方案|买什么、是否接受二手、是否付费选择退出安排|支付时间、总支出、预测转售与确认回购、自售和保障的并列比较|
|下一位使用者|接手与交付|接受成色/价格、选择交付窗口、确认或取消|含服务的到手总价、检测记录、交付承诺|
|检测/搬运服务商|服务任务台|接单、安排容量、记录完成或失败|任务窗口、工时假设、报酬、责任与异常|
|组织运营者|承诺与现金台|签多少、回购多少、留存多少、何时降价或暂缓新增承诺|逐笔现金、留存、应付款、库存成本、周转期、未来承诺|
|成员/共益治理者|规则与分配|检查进入门槛、费用、劳动报酬、纠错及补贴规则|群体差异、责任承担、可追溯例外；不做人的综合信用分|
|研究者/展示者|城市实验台|选择策略、假设、压力情景、对照和运行|可复现配置、结果范围、预测误差、实验归因与局限|

角色为原型视角与流程划分，本轮不把它冒充生产级账户权限系统。品牌与城市故事作为导览，不能代替这些具体操作。

## 执行顺序与验收

### M1：匹配正确性

先筛预算、品质、释放时间、整备时间、服务容量及截止期，再对可行候选排序。最低价候选不可行时继续搜索，不直接跳到新品。

验收：有“便宜但来不及＋稍贵且来得及”的回归案例；第二件被正确选择；容量不足时尝试其他可行窗口或服务商；无可行方案才回退。保持同种子复现、资源不重用、账目守恒和已签承诺不被追改。

### M2：持续流动与观察窗口

区分持续流入城市、明确停止新需求的退出压力测试。持续流动实验设预热、比较窗口与尾期处理；在同一计量窗口比较，未完成合同与库存单列，不能把未观察到的未来收入记作已收现金。

验收：持续场景比较窗口尾部仍有新需求；停止需求场景显式标注停止时间；报告期末未完成责任和库存年龄。不要一边改人口规模，一边悄悄保留旧总量分母。

### M3：同责任条件的对照

至少设置四组：无预测/无回购、有预测/无回购、无预测/有回购、有预测/有回购。每对预测比较须保持服务范围、资本、成本、需求和外部事件一致。推荐和回购的采纳分开建模，不因未采纳推荐就默认接受收费保障。

验收：提交逐组配置差异表；至少10个共同种子，正常和压力情景分列；提供配对差值而非仅比较独立均值。明确哪些改变属于预测，哪些属于回购定价/服务政策；不要求显著或正向。

### M4：把居民价值计入，但不虚构证据

并列展示：成功自售的事后成本、事前自售收益分布、确认回购价、时间与麻烦成本、确定性支付意愿。购买顾虑对是否购入/品质选择的影响作为待验证行为假设，与真实访谈或试点数据分开。

验收：金钱、时间、风险分别展示；不把“安心”随意折算成一个固定收益；未经校准的参数标明假设并做敏感性分析。即使有保障后仍更贵，也必须显示价格差和需要多少时间节省/支付意愿才值得。

### M5：把账做到角色都能看懂

一件物品可追溯每笔付款方、收款方、所有权、服务事件；平台有现金桥、留存桥、库存成本桥；经营结余、现金与估值严格区分，说明收入确认简化。服务费不能重复计入其他角色。

验收：单例每笔收支对平；城市期初现金＋现金流入−现金流出＝期末现金；留存不二次扣现金；未付费用不消失；未售库存不当作回款；消费者与平台的成本口径各自明确。

### M6：角色界面与展示

先做默认净水设备一条端到端任务链，再做取消与运力冲击。保留办公椅与床垫边界。每页说明“谁在看、现在需要决定什么、决定影响谁”，跨角色跳转保持同一物件与订单。

验收：居住者→组织→服务商→接手者→治理/实验的角色切换能解释同一单；一键回到固定案例；桌面与手机阅读检查；长任务可响应；下载报告标明v2，不覆盖v1结果。

## 最终交付门槛

- v1原始提交与实验可恢复，v2结果独立保存。
- 匹配回归、持续需求验证、责任一致的实验、三类财务桥全部通过。
- 发现零效应或负效应照实报告，给出可追溯原因及尚未识别的因素。
- 人群信用、真实付款、实际回购、法律组织形式均不因模拟界面而被宣称已经实现。
- 品牌价值主张以可交付的服务承诺为依据，不能先讲保证再用模型解释。
