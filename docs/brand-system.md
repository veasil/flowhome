# 栖流 Flowhome｜品牌文案与视觉系统 v1

> 使用说明：这是可直接进入原型的编辑稿。所有人数、价格、比例、实验差异与履约结果必须由同一次模拟运行生成；不得以示例数字代替计算结果。创始叙事为建议稿，发布前需由创始人确认事实口径。

## 1. 品牌核心

**名称**：栖流 Flowhome  
**主张**：居住有期限，生活不必将就。  
**一句话介绍**：栖流是一套共益城市生活原型，帮助人们按真实居住期限选择物品，并让物件、服务与承诺在城市里更可靠地流转。  
**解释句**：它把个人预算、未来供需、服务能力和经营约束放进同一座模拟城市，让每次推荐都能说明依据，也能看见代价。

**名称释义**：

- **栖**：一段值得认真生活的停留。
- **流**：人会迁居，物件可以继续服务，承诺必须留下记录。
- **Flowhome**：家不是固定地址，而是生活持续被安放的方式。

**品牌承诺**：给出有边界的建议；只做承担得起的承诺；把个人选择与城市后果一起呈现。

**语气**：温暖、直接、可核验。先说用户处境，再说选择；先说条件，再说结果；风险不用恐吓，失败不做粉饰。

## 2. 开场：城市模拟即首页

首页不是宣传封面，而是一张正在工作的城市桌面。

**状态眉题**  
`模拟城市 · 第 {week} 周 · 种子 {seed}`

**主标题**  
一座城市，正在决定下一件物品该去哪里。

**说明**  
调整居住期限、预算与服务容量，看看今天的选择如何改变未来供给、生活成本与履约风险。人物、地点、报价与供需均为模拟。

**主要操作**

- 开始本周推演
- 打开主案例
- 重置固定演示
- 查看模型边界

**顶部工作区**

1. **城市脉搏**：本周到期需求、可流转物件、服务容量、未到期承诺敞口。数值均取自当前运行。
2. **正在发生**：按时间显示迁居、释放、检测、预约、取消和结算事件。
3. **主案例卡**：净水设备，从“需要”进入“退出与下一位接手”。
4. **情景旋钮**：居住期限、二手偏好、周转资金、服务容量。

**主案例卡文案**

- 标题：住 12 个月，要不要为一台净水设备付完整周期的成本？
- 正文：输入期限、预算和使用偏好。系统先排除不合条件的方案，再比较净使用支出、服务可靠性、未来可流转性与承诺风险。
- 操作：比较方案
- 辅助：推荐是计算结果，不是购买要求。拒绝或自行购买不会影响参与资格。

**模拟标注**  
`模拟` 表示人物与事件由模型生成；`预测` 表示基于当前可见信息的估计；`已确认` 表示本次运行中已成立、不得被后续模型更新静默改写的承诺。

## 4. 页面级关键文案

### 城市总览

**标题**：城市不是背景，它会回应每一次选择。  
**说明**：一次购买会占用资金与服务；一次采纳会形成未来供给；一次取消也会留下库存、排程和现金变化。  
**指标名**：到期需求 / 可用物件 / 本周服务余量 / 最低现金余额 / 承诺敞口。  
**事件入口**：查看这次变化从哪里开始。

### 我的选择

**输入标题**：先告诉我们，这段生活会持续多久。  
**字段**：预计居住期限 / 预算上限 / 新旧偏好 / 安装条件 / 可接受服务窗口。  
**结果标题**：在这些条件下，有 {count} 个可行方案。  
**比较维度**：预计净使用支出 / 服务可靠性 / 退出路径 / 不确定性。  
**解释入口**：为什么进入候选。  
**无结果**：当前没有同时满足硬条件的方案。可以调整时间窗、等待供给，或自行购买；这不会影响信用记录。

### 物件旅程

**标题**：物件会离开一个家，责任不能中途消失。  
**轨迹节点**：进入使用 / 维护 / 释放意向 / 检测 / 整备 / 转运 / 再次使用 / 退出循环。  
**信息组**：当前使用者 / 所在片区 / 状态 / 下个预约 / 费用与收款 / 对应承诺。  
**床垫边界**：当前条件不足以支持可靠流转承诺。我们不会用一个好看的预估替代检测、卫生标准与可执行的退出路径。  
**替代选项**：选择新品并自行处置 / 选择短期租用方案（如当前情景可用）/ 等待符合条件的库存。

### 运营与信任

**标题**：信任不是一个分数，是一组可核对的记录。  
**四类记录**：信息完整度 / 物件检测 / 用户履约 / 服务方履约。  
**说明**：预计离开日期变化不自动算作违约；拒绝推荐不受惩罚。已确认订单未履行时，系统只记录相关事件与实际影响，并保留补正和申诉路径。  
**新人入口**：没有历史记录？可通过物件检测、分阶段履约或人工复核参与。  
**账目标题**：每一笔钱去了哪里。  
**账目项**：用户净支出 / 服务劳动报酬 / 平台单笔贡献 / 风险准备 / 库存价值估计 / 未到期承诺敞口。  
**拒绝承诺**：当前资金、运力或风险额度不足，无法新增保证。已有确认承诺保持不变。

### 策略实验

**标题**：不预设赢家，只比较后果。  
**B0**：自由购买与事后出售  
**B1**：提前登记与匹配  
**B2**：预测协调建议、报价与资源  
**说明**：三种策略共享人口、初始资产、偏好、外部事件与成本结构。结果显示均值、范围、分母、假设和失败情景。  
**压力情景**：集中离城 / 需求下降 / 服务容量下降。  
**指标组**：净使用支出 / 需求满足率 / 闲置时间 / 按时履约率 / 最低现金余额 / 劳动报酬 / 分群服务获得率。  
**结果脚注**：这是模拟结果，不代表真实商业收益、预测准确率或社会成效。

### 品牌与故事

**标题**：让短暂的居住，也拥有长期被照顾的方式。  
**正文**：人会因为学习、工作与家庭阶段迁居。生活用品却常按“长期拥有”来设计：买的时候承担完整价格，离开时独自面对搬运、折价和去向。栖流想把这个断点变成一条可说明、可履约的路径。  
**收束**：家可以是流动的，照顾不该是临时的。

## 5. 创始叙事建议稿

> 发布前需由创始人确认，不应补写未经确认的个人经历、地点或经营成绩。

栖流从两个很具体的物件问题开始。

床垫最接近“家”，也最难流转。它牵涉舒适、卫生、检测与搬运；如果条件不够，负责任的答案可能就是不做回购承诺。

净水设备看似标准，却把安装、滤芯、维护、拆卸和下一位使用者串在一起。只有把这些服务也算进去，“便宜”才可能成为真正的低成本。

这两个物件指向同一个问题：当居住期限变化，为什么生活品质、物件去向和服务责任总要由个人独自承担？

栖流因此被设计成一套城市生活原型。它不先承诺万物循环，而是先判断什么可以流转、由谁履约、资金和运力是否承受得住。能做的，给出透明路径；不能做的，清楚说明边界。

## 6. 共益经营原则

页面统一用“共益运营设计”或“共益城市生活原型”，不暗示已经取得法定资格或真实运营成效。

### 收入结构（设计口径）

- **协调服务费**：为匹配、排程和履约管理收费，成交前公开。
- **检测与整备费**：对应实际检查、清洁、维修与安装工作。
- **成员服务费**：如启用，必须对应明确权益，不以锁定退出制造收入。
- **资产相关收入**：如平台承担库存或回购风险，资产收益与风险准备分列，不混入服务收入。

**原则文案**：收入必须对应可说明的服务、劳动或风险承担；总交易额不等于公共价值。

### 分配与治理

- 服务劳动报酬单列，不用平台收入掩盖。
- 风险准备金先覆盖已确认承诺，再讨论扩张或分配。
- 价格、准入与承诺上限以版本化规则卡公开；修改只影响未来决策。
- 成员可提交规则建议，并查看采纳、拒绝与理由；涉及自身利益者回避表决。
- 群体结果按预算、居住期限和新老成员拆分，同时显示人数与分母。

**治理说明**：原型展示参与机制与政策参数，不宣称已有成员组织或完成现实治理验证。

### 信用原则

- 不建立泛化的人格信用总分。
- 信息完整度、物件状态、用户履约、服务方履约分别记录。
- 意向变化与明确违约分开；只让实际事件影响相关安排。
- 新成员可通过检测、分阶段履约或人工复核进入。
- 拒绝推荐、等待或自行购买不扣分。
- 平台和服务商的失约同样留痕，并提供纠错与申诉。

## 7. 视觉系统

### 字标

主字标固定为 `栖流 Flowhome`，中文为视觉主体，英文作小一层的同行标识。字形不使用房顶、钥匙或循环箭头等常见房产符号；在“流”的末笔加入一个向前的钴蓝栖点，既像当前位置，也像下一段路径的起点。单色场景保留字形与栖点的大小关系，不依赖渐变。

- 横版：`栖流` 与 `Flowhome` 左对齐，适合导航与封面。
- 紧凑版：只用 `栖流` 与栖点，适合移动端与图标。
- 安全区：至少为中文字高的 1/2；不与状态标签合并成一个图形。
- 背景：优先墨色底白字或白底墨色字；栖点使用钴蓝，青柠只作短时强调。

### 色彩

| 角色 | 色值 | 用法 |
|---|---:|---|

| Deep Ink | `#17203E` | 标题、正文、深色工作区 |
| Electric Lime | `#DCF78B` | 可行动机会、已满足条件、强调标签；配深色文字 |

| Clear Blue | `#A9BDFC` | 预测区间、次级数据层 |
| Cool Canvas | `#F5F6FA` | 页面底色 |

| Slate | `#64708F` | 次级文字 |
| Hairline | `#DCE1EC` | 边线与网格 |

整体以钴蓝与墨色建立可信度，用青柠提示“可行动”，珊瑚提示“需处理”。不使用米色、仿纸纹理或低对比大地色仪表盘。

### 字体与层级

- 中文：`Noto Sans SC / Source Han Sans SC / PingFang SC / Microsoft YaHei / sans-serif`
- 拉丁与数字：`Inter / Arial / sans-serif`
- 数据：等宽数字特性 `font-variant-numeric: tabular-nums`
- 标题短、字重 500；正文 400–500；辅助英文小字保留在栏目眉题，关键操作使用中文。

本版实现以钴蓝深浅变体、圆点、片区连线与时间轨迹为主。以下图形、状态形状和动效同时作为后续设计扩展规范；当前地图用颜色区分类别，状态以文字说明，未实现概率区间带或方向负载动画。

### 图形语言

- **栖点**：实心圆表示当前状态或已确认节点。
- **流线**：带方向的折线连接人、物件、服务和资金；线条宽度表达负载，不做无意义装饰。
- **时间窗**：半透明色带表示预计区间；实线边界表示确认窗口。
- **分叉**：并列展示“采纳 / 等待 / 自行购买”，避免把推荐画成唯一道路。
- **轨迹卡**：左侧时间、中央事件、右侧责任主体与资金影响。

### 界面构图

- 桌面端使用“城市画布 + 右侧决策栏 + 底部事件轨”的工作面，而不是平均尺寸的 KPI 卡片墙。
- 城市画布约占首屏 2/3，先呈现关系和变化；关键数字贴近对应的片区、物件或承诺。
- 右侧栏只保留当前情景的输入、解释和下一步动作；同一层级最多一个钴蓝主按钮。
- 卡片采用 12–16px 圆角与清晰细边，阴影极轻；用墨色区块建立节奏，不用米色底制造“生活方式”感。

### 状态语义

| 状态 | 文案 | 视觉 |
|---|---|---|
| 模拟 | 模型生成的角色或事件 | 冷灰底、虚线框 |
| 预测 | 基于当前信息的估计 | 浅蓝区间、波纹边 |
| 已确认 | 条件已成立的承诺 | 钴蓝实线、锁形标记 |
| 已完成 | 实际发生并结算 | 青柠底、墨色文字、勾形标记 |
| 需处理 | 取消、延迟或容量冲突 | 珊瑚描边、感叹标记 |
| 无法承诺 | 资金、运力或检测不满足 | 墨色文字、珊瑚侧条 |

颜色必须与文字、形状共同表达状态，不能只靠颜色区分。

### 动效

- 参数变化后，流线沿因果方向依次更新；总时长控制在约 400–700ms。
- 已确认承诺保持原位，新增预测在其后更新，视觉上明确“不会重写过去”。
- 取消事件先标记责任与时间，再展开库存、现金和排程影响。
- 支持减少动态效果；演示重置必须一键回到固定种子与初始周。

## 8. 通用短文案

**操作**：查看依据 / 展开约束 / 比较方案 / 保留选择 / 查看账目 / 提交申诉 / 回到当前周。  
**解释**：这些条件排除了什么？ / 这项承诺由谁承担？ / 哪个事件改变了结果？  
**加载**：正在重算城市状态…  
**完成**：已按当前条件更新。  
**无变化**：结果未变。当前修改没有触发新的约束或可行方案。  
**失败**：本次重算未完成，已保留上一次有效结果。  
**边界**：系统只使用当前时点可见信息与明确披露的意向，不读取未来事件。  
**页脚**：栖流目前是城市生活模拟与组织设计原型，不提供真实交易、征信或回购承诺。

## 10. 禁用表达

在真实试点完成前，不使用：

- “已降低成本 / 已减少浪费 / 已提高履约率”
- “精准预测 / 智能定价 / 保证回收”
- “认证共益企业 / 成员共同所有”（除非未来取得并可证明相应事实）
- “信用好 / 信用差”作为对人的总括判断
- “最优方案”作为无条件结论

替换为：`本次模拟显示`、`在当前假设下`、`预计区间`、`已确认承诺`、`当前条件不足`、`可行方案之一`。
