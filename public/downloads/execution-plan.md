# 栖流 Flowhome｜执行计划与验收标准 v1.0

状态：执行基线已确定；本文件为计划，软件、实验结果与商业验证尚未完成。

## 1. 交付目标

交付一个可操作、可解释、可重复演示的共益城市生活原型：用同一套模拟城市状态与计算结果，串联品牌故事、个人生活决策、市场供需、服务履约和组织经营。观众既能在约8分钟内看完一个完整案例，也能修改条件，观察连锁变化。

核心主张：居住有期限，生活不必将就。

组织定位：共益运营主体、本地服务合作网络、成员参与治理。此处是组织设计，不宣称已取得某种法定组织资格。

模型需要回答：今天的推荐、价格、回购承诺和履约安排，如何影响未来供给、用户生活成本、服务可达性及经营风险？

## 2. 固定范围与优先级

### P0：必须交付

- 一套品牌视觉与语言规范：工作名、主张、字标、字体、色彩、图形、关键文案及数据状态语义。
- 一座可重复运行的模拟城市：3个上海片区、1,000名模拟居民、600件初始物件、30个商品型号、8个服务商，104周。商品包括净水设备、办公椅、床垫。地理位置为示意，人物、报价和供需均为模拟。
- 一个有真实计算的模块化内核：硬条件筛选、有限信息预测、候选方案计算、容量与现金约束、状态更新、事件记录。
- 六个逻辑视图：品牌与案例入口、个人计划与选择、城市运行台、物件与履约轨迹、共益运营台、策略实验室。视图可采用标签或抽屉整合，不要求六个独立路由。
- 净水设备完整主案例；办公椅展示可流转决策；床垫展示条件不足时的拒绝承诺或替代安排。
- 三种策略的可重复对照、三项压力情景、成员群体结果及经营账目。
- 演示脚本、模型说明、实验记录和验收记录。

### P1：完成P0后再考虑

跨城市流转、更精细的预测模型、自动调参、复杂价格机制、多角色账号、完整资产所有权模式、真实商家试点、现场用户访谈。

### 不纳入本次交付

真实收付款、真实身份征信、真实回购承诺、注册共益组织、对接物流、真实用户自动画像。没有真实验证前，不把模拟结果表述为预测准确率、商业利润或社会成效。

## 3. 执行顺序与阶段出口

实施采用以下依赖顺序；每阶段达到出口后继续，无需额外逐阶段确认。范围重大变化另行记录。未获知活动截止日期，先使用里程碑，不虚设日历承诺。

| 阶段 | 主要工作 | 明确产物 | 阶段出口 |
|---|---|---|---|
| M0 故事与品牌骨架 | 固定主案例、组织角色、价值主张、视觉方向、页面信息结构 | 项目brief、品牌规范初版、8分钟脚本初版 | 每个故事节点都能指向输入、计算、行动或可观察结果 |
| M1 数据与城市状态 | 设计字段、单位、事件、随机种子、迁居与需求关联、资金及物件台账 | 数据生成器、数据字典、情景配置 | 同种子可复现；引用完整；物件、事件、账户状态有效 |
| M2 计算与服务闭环 | 实现有限信息预测、候选方案、承诺与容量约束、履约状态机、信任规则 | 无需界面也能运行的引擎、逐笔日志 | 主案例从需求到结算跑通；取消情景能产生真实成本和后续安排 |
| M3 软件与可视化 | 接入同一引擎，完成六个视图、参数操作和全局状态同步 | 可交互软件、统一视觉组件 | 修改参数实际重算；页面、图表、案例和账目来自同一次运行 |
| M4 共益规则与实验 | 完成策略对照、压力测试、群体分析、经营解释 | 实验结果、规则卡、资金曲线 | 可解释计算对市场、群体和个人决策的不同影响；如实显示失败 |
| M5 展示与交付 | 完成故事串联、文字视觉检查、设备检查、演示重置与导出 | 可访问演示、说明文档、最终验收记录 | 全部P0验收通过；残余限制明示；可独立演示 |

优先完成“数据—内核—单个case”的纵向闭环，再拓展全部界面；品牌骨架从M0建立，M3完整应用，M5收口。

## 4. 数据与算法实现要求

### 4.1 数据

分别记录居民意向、已确认承诺、实际事件、预测结果。预计离开日期变化，不自动计为违约。人物收入预算可以用于负担能力判断，学历、职业声望和社交活跃度不作为信用分。

数据必须表达至少五种关联：迁居引发需求与物件释放；价格影响接受意愿；维护影响状态与残值；集中离城影响供给和运力；推荐采纳影响后续供给。

模拟环境掌握的未来事件与算法可见信息分离。算法只能读取截至当前时点的信息和明确披露的意向，不得偷看未来成交者、取消事件或实际售价。

### 4.2 初版计算

预测层：使用当前意向、历史需求与可解释的季节假设生成未来供需情景；不把硬编码结果冒充学习模型。

决策层：先筛硬条件，再比较预计使用成本、服务可靠性、未来可流转性和经营风险；候选方案注明费用、成色要求、时间窗口、承诺主体及估计不确定性。

市场反馈：为用户保留拒绝、等待和自行购买选项，采纳概率是公开的模拟假设。每次采纳后更新未来供给及资源占用，避免重复分配一个需求或服务名额。

风控层：新承诺检查资金、运力和风险额度；条件不足时拒绝新增承诺或提供无保证服务。已经确认的回购条件不得因模型更新被静默降价或撤销。

状态层：记录拥有者、使用者、地点、物件状态、预约、服务任务和资金事件；一件物品同一时段不得同时被多个排他性使用者占用。

### 4.3 信任与共益

- 区分信息完整度、物件检测、用户履约、服务方履约，不生成一个泛化的人格信用总分。
- 新用户有通过检测、分阶段履约或人工复核参与的路径；无历史记录不能直接等同低信用。
- 平台与服务商也有承诺记录；纠错与申诉入口在原型中展示处理过程。
- 可参与的方案允许个人偏好优先；拒绝推荐不产生信用惩罚。
- 展示收费、劳动报酬、贡献和风险准备的关系。成员治理通过规则卡与政策参数表示，不冒充已经存在的成员组织。

## 6. 对照实验与压力情景

三种策略：B0自由购买与事后出售；B1提前登记与匹配；B2预测协调购买建议、报价和资源。

三种策略使用相同人口、初始资产、偏好、外部事件、成本结构及外部随机数；策略引起的后续变化属于结果，不能强行设成相同。实现时外部随机数按实体与时间固定，避免策略多调用一次随机函数就改变全部外部事件。

采用10个固定种子，运行标准情景及三项压力情景：集中离城、需求下降、服务容量下降。另对推荐采纳率和预测误差进行低/中/高敏感性检查，避免只在有利假设下展示。

模型参数在评估前固定；评估使用未用于调参的种子。若根据评估结果重新调参，需要另换评估种子。

主要指标：

- 用户净使用支出：购入与服务维护等已定义支出，减去实际收到的退出款项。没有完成退出的物件，实际收款与预测残值分开。
- 需求满足率：在需求时间窗内满足硬条件的需求数/到期有效需求数。
- 闲置时间：可供再次使用到下一次使用之间的时间；期末仍闲置物件单列，避免只统计成交物件。
- 按时履约率：在承诺窗口内履行的到期承诺数/到期承诺总数。
- 经营：单笔贡献、固定成本假设、最低现金余额、库存价值估计、未到期承诺敞口分别显示。
- 共益：上述指标按群体拆分，服务劳动报酬单列；不以总交易额代替公共价值。

报告各策略结果均值及范围、假设和失败情景。不设“B2必须胜出”作为验收条件；要求差异能被追溯和解释。若只展示成功种子、未来信息泄漏、预置胜出数字，则实验不通过。

## 7. 必须跑通的演示情景

| 情景 | 操作 | 应观察到的响应 |
|---|---|---|
| 居住期限变化 | 12个月改为6个月 | 在设计好的案例中重新比较可用服务与成本，说明为何变化 |
| 个体偏好 | 将可接受二手改为仅接受新品 | 不合条件方案移除，个人偏好不被网络收益覆盖 |
| 集中供给 | 增加未来一段时间同品类释放量 | 未来供需与风险变化影响新增推荐/报价；既有承诺不被改写 |
| 运力不足 | 指定一周服务容量下降 | 排程受限，展示延迟、替代资源或无法新增承诺 |
| 接手者取消 | 取消主案例后续接手 | 已承诺回购仍执行；库存、现金与后续任务更新 |
| 资金不足 | 下调可用周转资金 | 限制新增承诺并解释，不能悄悄透支账户 |
| 新成员与失约 | 新用户申请；已确认订单未履约 | 新人有可行参与路径；明确失约影响相关安排并留痕 |
| 高个体性物品 | 床垫条件不满足循环要求 | 拒绝提供不可靠的承诺，展示其他选择及适用边界 |

## 8. 交付包与完成判定

最终交付：可访问的软件演示；品牌视觉与语言规范；模拟数据生成器与字典；计算内核与配置；模型、服务、组织及经营说明；实验结果；8分钟演示脚本；验收与限制记录。源代码与运行说明随项目保存，支持重复运行。

完成意味着：功能、解释、视觉、实验和演示均满足上述标准。真实需求、预测有效性、付费意愿、履约成本及长期共益效果仍需后续试点验证。

如时间不足，依次缩减动画装饰、场景数量和品类深度。保留主案例、真实计算、模拟标注、账目一致性、异常分支和三类关系展示。任何P0范围调整需要显式修订本文件，不能无声删减。

当前完成项：执行计划与验收基线。下一实施动作：M0故事与品牌骨架，同时冻结供M1使用的实体、事件及主案例输入输出定义。
